## Remaining verification and limitations

- Both provider keys were subsequently configured in the Git-ignored private `.env`. Live `gemini-3.8-flash-tts` -> FFmpeg -> `whisper-large-v3` round trips passed for English ("The door is in front of you."), Arabic ("الباب أمامك.") and French ("La porte est devant vous."). Transcripts matched the phrases, apart from omitted Arabic punctuation. MP3 samples and a sanitized result manifest are in `mobile/native/.runtime/voice-live-test/`; secrets and samples are not committed. An earlier English STT-only call also passed using a synthetic Windows recording. These checks verify actual provider access and audio conversion, not phone microphone quality, listening comprehension or voice preference.
- Sideloadly installation completed with `Done` and `100%`. During phone testing, the voice-check result was below the visible Settings controls and the recorder was missing flattened native encoding fields; both were corrected. Subsequent requests from the iPhone to transcription and synthesis returned HTTP 200. This proves the requests completed, but final confirmation of displayed transcripts and audible answers remains outstanding. Voice quality/latency in all three languages, microphone sensitivity, speaker routing, interruptions and permission denial still need device acceptance testing.
- Google TTS subsequently returned HTTP 429. A single direct diagnostic on 2026-11-13 confirmed a daily limit and a provider `Retry-After` of 71,392 seconds at that moment. No Groq quota failure was confirmed. The app currently reports a generic voice-limit message, and the server normalizes quota errors to a 60-second retry hint, which does not represent this daily provider limit. There is no automatic retry or provider fallback. Switching off **Use API voice** selects the existing device STT and TTS together; independently choosing Groq STT with device TTS is not implemented.
- The existing native speech and wake-word behavior is covered by regression tests; the wake-word path has not been revalidated on the phone as part of this API-voice follow-up.
- Offline API tests mock account/provider calls. A later real HTTP test used a temporary account created through the running MySQL-backed signup endpoint: authenticated STT and TTS returned 200, and a speech request after logout returned 401. The test account was then removed with an exact user-ID/email ownership check. The existing team launcher started MySQL, RustFS, media, voice, dashboard/PWA and Metro for phone testing; its normal retention worker cleaned expired frames. Teammate source files were not edited.
- French voice is implemented. Member 2 still needs to confirm French support in `/ask`; changing STT/TTS does not implement French vision answers or the vision model itself.
- Shared `shared/contracts/api-v1.yaml` still documents Azure and EN/AR only. It should be updated by the team; this task preserves the endpoint/body/MP3 contract and keeps edits in Member 1's subtree.
- Dependency audit is not clean: the native tree still reports existing glob/minimatch tooling advisories and the pre-existing `react-server-dom-webpack 19.3.0` advisory. The new audio package is not the reported source. This native app does not serve React Server Components; upgrading its pinned React/renderer set is a separate coordinated dependency task, not evidence that the native speech feature failed.
